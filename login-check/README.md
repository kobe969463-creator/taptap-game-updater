# 游戏登录检测

逐个启动游戏，确认**能不能真正进到游戏里**；需要登录的，用 QQ / 微信一键授权登录完再确认一次。
建议排在 TapTap 更新之后、活动采集之前：线上采集每次都会先结束游戏再冷启动，登录态掉了的话采集会卡在登录页。

## 文件

| 文件 | 作用 |
|---|---|
| `system_prompt.txt` | 规则（系统提示）：动作格式、坐标规则、等待策略、登录时哪些按钮能点、哪些绝对不碰、判定标准 |
| `task.txt` | 任务：检测一款游戏的步骤，`{game}` 由运行时的游戏名替换 |
| `examples/task_和平精英.txt`、`examples/task_王者荣耀.txt` | 填好游戏名的版本，内容与 `task.txt` 一致，测试时直接用 |

## 运行

一次检测一款游戏，跑完即结束；多款游戏由外层脚本按手机的游戏清单逐个跑，互不影响。

```bash
cd /path/to/autoglm && python run.py --device <设备ID> --game "和平精英" \
  --prompt-file /path/to/taptap-game-updater/login-check/task.txt \
  --system-prompt-file /path/to/taptap-game-updater/login-check/system_prompt.txt \
  --max-steps 60 --run-label login-check
```

> 需要入口支持 `--prompt-file` / `--system-prompt-file`（用自定义 prompt 跑一次任务）。
> 接进本仓库的 `update_games.py`、做成批量 + 定时是下一步。

结束信息就是检测结果：

| 结束信息 | 含义 |
|---|---|
| `《X》无需登录，已进入游戏` | 本来就是登录态 |
| `《X》已完成登录并进入游戏（QQ登录）` | 走完授权后进入 |
| `需要人工：…` | 需要输验证码、扫码、实名、人脸等，脚本不碰 |
| `《X》进入失败：卡在xxx` | 进不去，附卡住的位置和屏幕内容 |

## 设计要点

- **登录步骤不写死**。不按固定步数点，按按钮语义走：「继续 / 授权 / 登录 / 同意 / 确认 / 允许 / 下一步」可以点，
  「取消 / 拒绝 / 切换账号 / 更换登录方式 / 注册 / 退出登录」不点。实测两个游戏的登录入口文案、授权页数都不一样，都能走通。
- **登录页可能只是加载过场**。有的游戏加载时会闪过登录页，等一会儿自己就进去了。所以第一次看到登录页先等 15–20 秒再判断，
  仍停在登录页才去点，避免多余点击。
- **判定只看一条**：是否真的进入了游戏（大厅 / 主界面、「开始游戏」按钮，或选区 / 选服页）。
  登录按钮消失、弹窗关掉都不算。进了大厅立即结束，不去逐个关活动弹窗。
- **不碰的事**：账号密码、手机号、验证码、扫码、实名认证、人脸识别、充值、开始对局；游戏内提示要更新版本也不在这里更新
  （交给更新任务）。遇到就结束并返回「需要人工：…」。

## 实测（2026-09-19，红米 Note 12T Pro，qwen3.8-flash）

| 场景 | 步数 | 结果 |
|---|---|---|
| 和平精英，需要登录 | 14 | 关公告 → QQ 登录 → 授权三页（同意 / 确认 / 同意）→ 进入大厅 |
| 王者荣耀，需要登录 | 9 | 同意服务协议 →「与QQ好友玩」→ 授权两页 → 授权后退回登录页，自行重试一次 → 进入大厅 |
| 王者荣耀，已登录 | 3 | 看到「开始游戏」和区服信息，判定「无需登录」 |
| 和平精英，登录页为加载过场 | 5 | 先等待不点，自动进入大厅，全程未点登录按钮 |

两个游戏的登录流程完全不同（入口文案、授权页数、中途退回），提示词里都没写，全靠上面的语义规则现场判断。

**还没验证到的**：需要人工的情况（验证码、实名、人脸）、选区 / 选服页面、网易系游戏。
